# Stock and costing changes: developer checklist

Use this checklist whenever a new or changed transaction can affect physical stock, reservations, valuation, WIP, settlement, COGS, or rollback. A transaction is not safe merely because it calls a shared service.

1. **Impact Manifest & Contract Registration**: Map each public post, rollback and repost route, its permissions and trusted company/branch, stock item, warehouse, location, lot, status, base UOM, business date and document owner. Identify affected Inventory, Procurement, Production, Sales, QA and Subcontract records, downstream readers/reports (including FG cost trace, Gross Profit, Month-End Snapshot), and active generations. Record the route in [productionv2_backdated_replay_impact_manifest.md](../plans/productionv2_backdated_replay_impact_manifest.md) and [costing-transaction-matrix.md](costing-transaction-matrix.md) before removing any safety blocker.
2. **Coordinator, Chronology, Business-Date & Period Guards**: Use the existing `IStockPostingCoordinator`, valuation, and replay services where applicable, keeping transaction-specific authority in its owning module. Enforce the shared business-date rule on every public stock/value route: allow future-dated drafts only in an open period (`IvPeriodCloseGuard.EnsureOpenAsync`), refuse posting when `TransactionPostingDateGuard.FutureDateError` triggers, and recheck open-period status under the branch transaction lock for both the candidate date and any reversed posting's original `EffectiveAt` (`StockPostingCoordinator` enforces both on reversals). Plan dependencies before mutation, then recheck the plan, source evidence, stock, period, policy, QA physical/logical/receipt holds, and concurrency tokens under the branch lock. Unsupported or unproven histories must fail atomically without partial writes.
3. **Active Generation Resolution & Reconciliation**: Never assume the original `StockValuationFact`, `PoCdnCostAdjustment`, `ProductionBalLotMovement`, `StockFifoLayerConsumption`, or `StockCountReplayGeneration` is still active when reading, rolling back, or reposting. Resolve active generations via `StockReplayValuationGenerationResolver`, `ProductionReplayEffectiveCostReader` / `ProductionEffectiveCostResolver`, and `StockReplayPurchaseVarianceGenerationReader`. Reconcile each physical slice and item-level quantity/value before and after post, rollback and permitted repost. Check WAC, FIFO layers or Standard Cost as applicable, and reconcile affected WIP, settlement, COGS, return allocations, and QA holds. Preserve immutable facts, original owners and audit lineage.
4. **Mandatory Regression Tests**: Add transaction-specific tests for normal and backdated post/rollback/repost; later receipts, issues, counts, transfers, purchase notes, production outputs/FG, and sales/returns; negative historical stock; closed periods (draft, post, and rollback of closed-period postings from a later open period); future-dated draft vs refused post; QA holds; failed writes; duplicate and competing requests; and month-end reconciliation. Include both successful paths and atomic refusal of unsupported shapes. Add cross-module regressions proving existing transactions and readers (including FG cost trace and Gross Profit) remain correct when the new transaction is inserted or removed.
5. **Gate & Full-Suite Execution**: Run the focused gate below (passing `-ResultsDirectory <scratch-dir>` when keeping repo `TestResults` clean), all additional affected-module tests, and the full regression suite before release. For replay or locking changes, also run relevant SQL Server tests against a disposable database. Record pass/fail/skip counts, database provider, unsupported combinations and any tests not run.

## Repeatable focused gate

From the repository root, after restoring the project's dependencies:

```powershell
powershell -NoProfile -File scripts/testing/run-costing-regression.ps1
```

Add `-IncludeSqlServer` to also run the selected receipt replay concurrency and failure tests in newly created, identity-checked scratch databases on `.\SQLEXPRESS`. Specify another test server with `-SqlServer`; the account must be allowed to create and remove its own scratch databases. The script checks the selected test groups and fails on test failures, missing required groups or skipped tests. `-NoBuild` uses the existing test build.

The gate is a **focused subset**. Its SQL checks cover selected receipt scenarios, not every transaction, costing method or cross-module dependency. Extend the selected groups and scratch scenarios when the transaction impact map requires it. It does not prove production readiness or replace the full suite, performance checks and manual review in the replay plan.

The current Subcontract inventory and Production posting adapters are blocked. The focused gate runs their existing blocking tests so stock and WIP posting cannot be enabled without replacing that safeguard with the required costing, replay and rollback coverage.

Some existing SQL Server tests read the application's default connection string. Do not run the full suite against an operational database; first configure and verify a disposable test database and the selected test fixtures. The focused gate overrides the default connection and clears selected test connection settings for its local test phase; its optional SQL checks use the dedicated scratch runner.

Repository CI enforcement is configured via [costing-regression-gate.yml](../.github/workflows/costing-regression-gate.yml) (triggering on pull requests and pushes to `productionv2` and manual `workflow_dispatch`; configure the `DEVEXPRESS_NUGET_FEED` repository secret if using a private DevExpress NuGet feed, and require the `Build & Focused Costing Regression` check in branch protection rules). A local pass alone does not replace branch-protected CI enforcement or SQL Server/volume verification.
