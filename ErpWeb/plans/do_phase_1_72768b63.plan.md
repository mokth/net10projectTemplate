# Sales Delivery Order Phase 1 — hardened v3 (P0 contracts)

Standalone DO only. UI/commercial/FX/save match invoice. **Stock-out on DO post.** Invoice screens unchanged except shared SP rename. Invoice-from-DO later.

This revision adds the five P0 contracts from the architecture review. Implementation must follow these contracts; UI rights are not sufficient.

## Status

```mermaid
flowchart LR
  NEW -->|Post| POSTED
  POSTED -->|Rollback| NEW
  POSTED -->|ForceClose| CLOSED
```

- **NEW**: edit, delete, shipment, post
- **POSTED**: rollback (stock restored, **SP kept** as NEW) or Force Close
- **CLOSED**: Force Close only; view-only; later billing rejects CLOSED; **no PARTIAL**
- Max 3 Post/Rollback/ForceClose (`MaxPostSelection = 3`)
- No month-end gate

## Out of slice

Invoice pick-DO / LinkDO, PARTIAL, SO import/qty, credit limit, print, save-and-post, barcode, catch weight, OPEN/Refresh, header-only save, changing invoice `DoNo = InvNo`.

## P0-1. Authorization + tenant scope (every operation)

Reuse invoice helpers: `ValidateUserContext` / `ValidateWriteContext` (`TryBranchScope` / `TryWriteScope`) and `_accessRights.CanAsync(MenuCodes.SalesDeliveryOrder, permission)`. Do not invent a second authz API. UI `MenuAuthorize` is not sufficient.

**Fail-closed on CompanyCode and BranchCode** (write also requires LocationCode via `TryWriteScope`, same as invoice). Empty/missing scope returns an error result — never query.

**Never load by `DoNo` alone.** Every keyed load is `(CompanyCode, BranchCode, DoNo)` from authenticated scope, never from the request body/route as tenant.

This app uses `PermissionCodes.Access` (not VIEW).

- **GetLookups / GetCustomerDefaults / ResolveCurrencyRate / Search / Get:** ACCESS; `TryBranchScope`; Company+Branch
- **SaveNew:** ADD; `TryWriteScope`; Company+Branch+Location; insert (no RowVersion)
- **Update:** EDIT; `TryWriteScope`; Company+Branch; **RowVersion required**
- **Delete:** DELETE; `TryWriteScope`; Company+Branch; **RowVersion required** per selected row
- **AddShipment / ReplaceShipmentLine:** EDIT; `TryWriteScope`; Company+Branch; **RowVersion required**
- **GetShipmentEdit:** EDIT; `TryWriteScope`; Company+Branch; no RowVersion (read)
- **Post:** POST; `TryWriteScope`; Company+Branch; **RowVersion required** per selected row
- **Rollback:** ROLLBACK; `TryWriteScope`; Company+Branch; **RowVersion required** per selected row
- **ForceClose:** CLOSE; `TryWriteScope`; Company+Branch; **RowVersion required** per selected row

Denied permission → `Authorization` fail (same message shape as invoice Post). Wrong company/branch → **NotFound**, not a leak.

List DTO **must carry `RowVersion`** so list Post/Rollback/ForceClose/Delete can send the token (stricter than current invoice list Post, which omits it).

## P0-2. Universal RowVersion contract

Applies to every mutation except SaveNew:

1. Reject missing/empty `expectedRowVersion` with `Concurrency` (same as invoice Update).
2. `LockForUpdateAsync` with `UPDLOCK, HOLDLOCK` on `(CompanyCode, BranchCode, DoNo)`.
3. Set `OriginalValue` to the client token (after optional byte equality check, same as invoice).
4. Perform the full mutation in **one transaction**.
5. `SaveChanges` + commit, or `DbUpdateConcurrencyException` → rollback → `Concurrency` fail.
6. **No partial state:** SP delete, status change, and stock core are in the same txn. First failure in a batch of 3 stops remaining items (`Not attempted`), same as invoice Post.

SQLite tests: `TouchRowVersion` GUID bytes (invoice pattern). SQL Server: DB `rowversion`.

## P0-3. List query shape (no unbounded list)

Clone [`SaInvoiceRepository.SearchPagedAsync`](ErpWeb.Model/Repositories/Sales/SaInvoiceRepository.cs), then tighten:

- Filter: `CompanyCode` + `BranchCode` from scope only
- Optional: Status, DoDate from/to (to exclusive next day), search on DoNo / CustCode / CustName
- Sort: allow-list `DoNo`, `DoDate`, `Status`, `CustCode`, `TotAmnt`, `CreatedDate`; default `DoDate desc, DoNo desc`
- `Skip >= 0`; `Take` clamped **1..100** (`MaxPageSize = 100`); default 20
- `AsNoTracking()`
- **No `Include(Details)`**
- Project to list DTO columns only (DoNo, DoDate, Status, CustCode, CustName, TotAmnt, RowVersion, CreatedDate, CreatedBy)
- LineCount: second query for the **page of DoNos only** (`GroupBy` + `Contains` on ≤100 keys), same as invoice
- Compact preview Take = 50 (already under max)

Grid custom data source must pass Skip/Take from DevExpress options (invoice `SaInvoiceGridDataSource` already does). Do not load all DOs into memory.

## P0-4. Indexes (from real access paths)

Do **not** create every column combination. These match the queries above plus SP lock/delete.

**SaDO**

- PK clustered: `(CompanyCode, BranchCode, DoNo)` — Get/Lock
- `IX_SaDO_Company_Branch_Status_DoDate` on `(CompanyCode, BranchCode, Status, DoDate)` — list status + date range + default sort
- `IX_SaDO_Company_Branch_CustCode` on `(CompanyCode, BranchCode, CustCode)` — search/filter by customer (replace current `IX_SaDO_Company_CustCode` which omits Branch)

**SaDODetail**

- Unique: `(CompanyCode, BranchCode, DoNo, Line)` — FK/line identity
- Line-count query uses this unique key prefix `(CompanyCode, BranchCode, DoNo)`

**IvTrxBatch (SP lock / ForceClose / delete)**

Today [`IvTrxBatchConfiguration`](ErpWeb.Model/Configurations/Inventory/IvTrxBatchConfiguration.cs) has no RefNo index. Add:

- `IX_IvTrxBatch_Company_Branch_TrxType_RefNo` on `(CompanyCode, BranchCode, TrxType, RefNo)`
- Unique filtered (SQL Server): `UQ_IvTrxBatch_SP_Ref` on `(CompanyCode, BranchCode, RefNo) WHERE TrxType = 'SP' AND RefNo IS NOT NULL` — one SP batch per document ref; invoice and `DO/{doNo}` cannot collide

Lock/delete **must** filter `CompanyCode + BranchCode + TrxType=SP + RefNo`. Never RefNo alone.

## P0-5. Schema migration safety (DoNo PK → Option A)

Manual DBA, not app startup. Template: [`scripts/alter-sainvoice-option-a.sql`](scripts/alter-sainvoice-option-a.sql). Script must **RAISERROR and stop** on any failed gate. Do not invent HQ/branch.

**Pre-checks (read-only, print counts)**

1. `SaDO` / `SaDODetail` exist.
2. Header `CompanyCode` and `BranchCode` not null/blank. Fail if any blank — DBA backfills; script does not guess.
3. Duplicate detect: `GROUP BY CompanyCode, BranchCode, DoNo HAVING COUNT(*) > 1` — fail if any.
4. Detail FK: every detail `DoNo` exists on header; after backfill, detail Company/Branch match header.
5. SP refs: list `IvTrxBatch` SP rows whose `RefNo` equals a `DoNo` or `DO/{DoNo}`; print counts. Phase 1 new writes use `DO/{DoNo}` only. Do not rewrite historical invoice SP (bare InvNo).
6. Orphans: details with no header; SP `RefNo` pointing at neither invoice nor DO — print, fail if DO-detail orphans > 0.

**Apply (one change window)**

1. Add missing columns (`CurrRate`, `RowVersion`, post/rollback audit, detail Company/Branch, `StockControl`, discount stack, etc.).
2. Backfill detail Company/Branch from header (same as invoice alter).
3. Re-run duplicate / blank / orphan gates.
4. Drop old PK/FKs on `DoNo` only.
5. Create unique detail index; add composite FK `SaDODetail` → `SaDO` cascade.
6. Create clustered PK `(CompanyCode, BranchCode, DoNo)`.
7. Create list/SP indexes in P0-4.
8. `ALTER` `IvTrxBatch.RefNo` stays nvarchar(50) (`DO/` + 30 fits).

**Validate**

- Header count before = after
- Detail count before = after
- Orphan detail count = 0
- Duplicate Option A key count = 0
- `IX_IvTrxBatch_Company_Branch_TrxType_RefNo` exists

**Rollback**

Keep a pre-window backup. Reverse script is restore-from-backup, not an in-place PK downgrade. Document that in the script header.

**Empty DB:** `scripts/create-sado.sql` creates Option A from scratch (no alter).

**StdPsize lock:** column stays `StdPsize`. Map to calc `StdPackSize` in DTO only. `SoNo = ""` never null.

## Tests

**Existing v2:** SaveNew DO numbers; IDOR; AppInvoice/AppShip; post without e-invoice gates; POST_NO_LINES; `DO/` vs bare INV RefNo; rollback keeps SP; ForceClose balances unchanged; CLOSE/POST denied; CLOSED blocked; MaxPost=3; SoNo `""`; leftover stamp; invoice regression after rename.

**Idempotency:** Post already POSTED; Rollback already NEW; ForceClose already CLOSED; Delete missing/NEW-already-gone — fail status, no second stock/SP effect.

**Races (SQL Server):** Post vs ForceClose; Rollback vs ForceClose; Update vs Post; Shipment vs Post; Delete vs Post. Winner commits; loser concurrency or status fail; no mixed CLOSED+posted-stock-reversed.

**Stale RowVersion:** ForceClose / Post / Update / AddShipment / Delete with old token → Concurrency, txn rolled back.

**SP scope:** wrong-company SP with same body never deleted; wrong-branch never deleted; invoice bare RefNo does not match `DO/{no}`; accidental bare-DoNo SP is not the DO batch (lock uses `DO/` prefix only).

**List:** `LargeDoList_IsPaged` (Take clamped, total > page); `ListQuery_DoesNotLoadDetails` (no detail graph).
