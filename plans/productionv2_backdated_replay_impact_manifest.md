## Shared gates and readers

- `StockPostingCoordinator.ExecuteAsync`/`BeginInTransactionAsync` acquire the branch lock before the callback. A read-only impact plan must be built by the caller before that entry; a stale plan must be retried outside the lock.
- Caller-owned V2 postings now have an abort/SQL-session cleanup seam, including direct Production and Procurement coordinator users and Inventory/Sales wrappers. SQL Server pooled-connection failure tests are still required; SQLite cannot verify the session marker.
- `IvInventoryPostingService.Chronology` contains `ValidateBalanceStockDate` and `ValidateNoLaterDayMovementsAsync`; `InventoryValuationService` contains `RejectBackdatedPoolsAsync`. They stay on the non-replay path until an under-lock physical and financial proof replaces them.
- `StockValuationSnapshotBuilder` is the period-close financial reader. Its active FIFO issue check now excludes reversal facts. `IvPeriodCloseService` calls it.
- `ProductionOutputService.SharedWip`, `ProductionFinishedGoodReceiptService.CostTrace`, `ProductionPoolValuationService`, and `ProductionWorkOrderTransferService` read append-only allocation/dependency edges. They now use a shared active-edge resolver. FG trace and PADJ/WO owner checks still require foreign-writer lineage handling before replay can write their corrections.
- `StockValuationQueryService` supplies as-of value and invoice COGS. `InventoryAsOfStockService` supplies physical as-of; both need canonical count keys and corrected active generations before replay can be enabled.

## Current implementation boundary

The event key, read-only physical simulator, database-backed active physical-tail reader, and pre-lock physical insertion/removal plans, including a count-line-derived end-of-day candidate, are in place. A sheet-level count plan groups all counted piles under one epoch/watermark and rechecks the complete counted-line set and each slice under the root lock. The reader keeps count adjustments at their canonical end-of-day key, excludes their midnight history legs from ordinary events, and removes reversed ordinary histories. It resolves an active foreign Inventory replacement through its `StockReplayEffect` and original history to the business owner's effective time, sequence and line identity; a missing or ambiguous owner link fails the read. This reader contract requires replacement effects to link directly to the original owner history. The plans capture an epoch, branch sequence watermark, pile rowversion and deterministic hash. A validated sheet permit carries immutable line projections through the root's physical and header mutations. A count-anchor command factory snapshots counted quantities and proposed cost bases, rejects missing positive-line cost authority, uses canonical end-of-day time, and derives a deterministic request ID and fingerprint; it is not yet called by `IvStockCountService`. A guarded count-owned ADJ fast seam stamps legacy history at midnight under the end-of-day V2 root. An initial-generation writer verifies the whole sheet, final live piles, exact ADJ histories and cost bases against the root's frozen snapshot, and appends a generation for every counted line, including zero-effect lines. Focused tests seal zero and inbound count roots and exercise an outbound adjustment; the writer is not yet routed from the count service. A new correction permit compares each later count's frozen observation with the replayed delta under the triggering root, and a correction writer verifies the old active leaf, original anchor, root candidate and ADJ reversal/replacement histories before appending a child generation. Its reversal helper assigns a new correction batch and caller-selected root posting line. An integration test exercises +4 to +2 correction without changing the original count anchor. The correction writer is not yet routed from any public posting service, and full financial replay is still missing. Replay completion verifies required Inventory valuation generations and exact root reversal facts before sealing without normal valuation. Draft/post date gates, active Production edges, FIFO receipt-reversal close classification, and the IP rollback revision flush have focused tests. EF entities define count anchors' cost basis/generation lineage and replay-run/effect evidence; active count-generation, complete inventory valuation-set, and Production effective-cost readers are present. Generic ADJ post/rollback rejects a batch linked to a V2 count generation. The legacy count service also rejects repost, rollback, Recover, cancel, and observation edits for any sheet with V2 generations, so it cannot mutate that lineage before its replay-aware route is ready. The WAC count fallback recomputes an original six-decimal unit cost and hash from sealed V2 facts at the anchor watermark. Linked `COUNT_FROZEN_V2` and explicit manual/zero approval receipts validate their basis, count, anchor, adjustment history, and generation before using a six-decimal fallback on an empty pool; malformed hashes or approval evidence fail atomically in focused integration tests. FIFO now accepts verified manual/zero fallback when the replayed pool is empty; ledger-derived FIFO fallback still needs historical layer reconstruction. Approval capture in the count UI/writer remains missing. Standard count valuation verifies the frozen approved revision against the count event and uses the event-date Standard Cost. A strict V2 physical as-of reader unwinds the active canonical timeline without clamping and has midday/end-of-day count tests; it is not yet used by the general as-of service or count generation. The count service still uses live quantity and retains the legacy seven-day Generate/Post safety limit. No replay rollout flag is enabled. SQL Server concurrency tests, downstream propagation, and production readiness gates remain outstanding; database migration was deferred for the current development pass at the user's request.
