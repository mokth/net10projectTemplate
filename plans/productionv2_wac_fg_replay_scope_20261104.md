# Open-period WAC finished-goods replay: impact and verification

- Base: `productionv2` at `ed703f6665d90cc979043395afd3089ec36fdd86`. The bounded replay changes are carried from `cebb854`, without its unrelated Purchase, UI or data-protection changes.
- The receipt-lock follow-up was built and tested on `productionv2` at `8275ee3` with the follow-up changes applied.
- Public routes: Inventory MR/GR post and rollback, Production material issue and Daily Production, and finished-goods post/rollback. The bounded case is one source receipt, one issue, one output and one terminal FG receipt in the same open period under WAC.
- Ownership and locking: preserve the original receipt and FG owners, their active valuation and Production generations, replay effects, branch watermark and plan hash; rebuild the plan inside the existing branch transaction. A missing, reversed, ambiguous or foreign owner must reject the entire root.
- WAC MR and GR posting now locks the source batch before its under-lock proof and retains that lock through the receipt write and seal. Receipt rollback takes the same lock before checking and reversing its source. Draft edits use this batch lock, so they cannot replace an approved line during posting.
- Quantity and value: reconcile each company/branch/item/warehouse/location/lot/status/UOM slice, item WAC state and both Production pools. In the SQLite fixture the RM slice starts at 20 EA, issues 4, and changes from 16 EA/32 value to 21 EA/75.6 after a 5-EA backdated receipt; the 2-EA FG receipt changes between 6 and 9.2 value, with the remaining WIP matching its output. Receipt removal and final issue reversal must restore the corresponding quantities and values without duplicate physical stock.
- Repost must belong to the same source receipt. Missing FG or output correction ownership, a different receipt at the same price, closed periods, negative stock, malformed reversal pairs and injected failure must leave stock, WIP, PO quantity and audit state unchanged.
- A public WAC test exposed an unreconciled historical FG reversal: after source replay the expected FG cost was 9.2 while both reversed Production movements still held 6. WAC and FIFO now refuse this uncorrected reversed-FG route if the projected FG value changes; unchanged-value cases remain eligible. If FG was posted at a corrected WAC value, its source receipt must be removed before the FG receipt can be rolled back. A separately verified correction of an active FG followed by its reversal retains its bounded source-removal path.
- A second public test exposed the same issue when a Production output had been reversed without any FG receipt: WAC and FIFO MR/GR accepted a source cost change while leaving the output and its reversal at their old effective values. The bounded case now restates the affected consume/produce and their exact reversal together, preserving frozen conversion and immutable source facts. Other output inputs must have exact unchanged reversal costs. The source pool retains its full corrected issue value and the output pool remains zero. Tenant, sealed owners, both open periods, generations, movement identities, pools and replay lineage are checked in the root transaction. Repeated receipt post/rollback restores prior effective values without duplicate active restatements. Wider graphs and cost-changing replay through an uncorrected reversed finished-good receipt remain blocked.
- An isolated WAC backdated MR/GR can post after an unconsumed Production issue has already been reversed, even when the receipt changes the issue's cost. The same root writes paired zero-quantity Inventory value corrections at the original issue and reversal dates and paired Production cost restatements. Receipt rollback reverses both pairs in its own root; repost validates the cleared history and can repeat the cycle. Under the branch lock the route verifies one receipt line, one item/pile, no other relevant history, output, count or invoice settlement, open dates, sealed matching owners and facts, exact material/pool reversal lineage and nonnegative historical stock. GR purchase and QA checks remain in force.
- The isolated WAC route also removes a receipt originally posted before the issue and reversal when removing it changes their cost. Its rollback creates paired Inventory and Production corrections; repost verifies and reverses the previous pair and writes a replacement when the approved receipt quantity or price changes the issue cost. Repeated removal, edit and repost are supported for a single existing pile; a GR must keep its original PO line. A projected rounded cost that cannot reconcile the resulting pool is refused before posting, so the receipt does not become unrollbackable. An original receipt already owning unrelated replay effects, finished-good descendants and broader histories remain guarded. Editing MR or GR preserves the draft's posting revision so an approved edit after rollback does not reuse an old posting identity. A Production issue with an active cost restatement must be rolled back only after its source receipt is removed or otherwise reconciled. Proven Standard-cost issues and later-dated receipts remain eligible; missing or changed evidence is refused.
- A later-dated reversal must not erase the original physical event from historical stock between those dates. The V2 as-of reader now restores that interval using exact sealed original/reversal owners, the canonical event key and the reversal's physical slice. This also corrects stock-count candidates and Production allocation checks; it does not change the active valuation replay tail. The fast V2 issue, transfer and negative-adjustment paths check transaction-time stock under the branch/slice lock, including when replay is disabled. The pending count exception is limited to the verified unsealed count anchor and retains the count's end-of-day time.
- Fast MR/GR rollback checks the historical balance at a later reversed Production issue's event key before removing the receipt. This closes a reproduced case where a later 21-EA issue and reversal left 25 EA live, but removing the 5-EA receipt would have made the earlier issue 1 EA short. A later count is refused on this bounded fast path. Changed-cost WAC removal now uses the separate paired correction route above when the exact isolated proof succeeds. These checks do not establish safety for every other reversed movement or FIFO dependency.
- The reversed Production issue guard also runs for receipt posting when backdated replay is disabled. A public MR and GR witness showed that a receipt into one pile could otherwise post before an issue and reversal on another pile of the same WAC item, leaving both issue costs stale. The guard checks the item-wide dependency under the branch lock and refuses an unproven cost change atomically. It still permits only the previously verified unchanged-cost exception. Ordinary active later issues already have a separate valuation chronology guard.
- The read-only WAC simulator can bind an exact Production issue reversal to its earlier issue and restore the projected issue value for receipt insertion and removal; it rejects missing, duplicate, partial or mismatched pairs. The ordinary tail writer still refuses these bound reversals. The separate isolated route above uses a narrower proof and paired Inventory and Production correction writer.
- The isolated proof checks both affected periods for a changed cost. The older cost-neutral safeguard retains its stricter unchanged-price and value conditions even if rounding makes the issue total look unchanged. The changed-cost route uses the proof only together with atomic paired corrections and verifies their ownership before rollback or repost.
- Production issue detail now shows the effective replayed unit and total cost for a corrected active issue, including FIFO splits, and restores the original cost after receipt rollback. The read verifies sealed Production replay ownership and reconciles it with the complete active Inventory valuation generation. Missing or inconsistent correction evidence fails the cost-visible read; users without cost-view permission continue to receive masked costs without reading those values. Original posted material facts remain immutable.
- SQL Server exposed a stale-draft race in finished goods: editing only the batch header or its lines did not update the receipt row whose rowversion is checked on POST. Every existing-draft save now advances that rowversion within the same branch-locked transaction. SQL cases verify both header-only and line-only edits reject a stale POST, while valued FG rollback, idempotent retry and repost continue to work.
- Test public MR and GR, higher and lower WAC costs, repeated post/rollback, the supported FG rollback orders, original and corrected evidence, period close, and adjacent Production/Inventory regressions. SQLite does not establish SQL Server lock, concurrency or session-context correctness.
- Outside this bounded change: FIFO value-changing FG replay, multiple FG/output dependencies, subsequent FG stock events, corrected cost trace, unsupported reversal orders, production enablement and migration. The user explicitly deferred migration while development continues.

- The isolated WAC route also supports MR/GR when both the Production issue and its single output have been reversed, with full or partial consumption, whether the receipt was initially posted before or after the issue. It preserves an unchanged additional output input and frozen conversion costs, and corrects both the original and reversal of the issue, consumption and output in the receipt root. The route checks receipt-owned correction histories, both output periods, the exact dependency and allocation reversals, and zero WIP pools; other graphs remain guarded. A partial consumption receives its proportional issue value. A cost change that rounds to no change in the consumed portion is refused to preserve a reversible correction history. An earlier receipt can be rolled back, edited for price or quantity, and reposted when the same reconciliation succeeds.

- FIFO receipt rollback checks the historical layer splits of a later reversed Production issue. A reproduced MR case removed a 5-unit receipt even though its issue had consumed two units from that receipt: the issue and reversal stayed at 24 when they should have been 8. With replay enabled and the evidence store and guards present, the bounded route now corrects this history for MR and GR. Without that proof or with replay disabled, the earlier unsafe removal remains blocked.
- With replay enabled, an MR or GR entered after the Production issue has already been reversed can be backdated, rolled back and reposted, including when the issue's FIFO allocation and cost change. The same route supports an earlier receipt that was originally posted before the issue. Ordinary receipts with the same timestamp are ordered by their verified posting sequence; the source and earlier layer must have distinct, exact sealed owners. Count-owned or unproven same-time layers remain blocked. The guard proves the sealed issue and reversal owners, matching Inventory and Production movements, FIFO consumption/reversal and open-period policy, and rejects unsupported intervening histories, output dependencies and damaged evidence. QA holds remain effective.
- The FIFO reversed-issue guard validates each split's unit cost from its exact stored amount and quantity, matching the valuation writer's rounding. Multiplying the rounded unit cost back by quantity could differ by one six-decimal unit and wrongly reject a valid split. Public MR/GR cycles now cover that case and reject a damaged unit cost while preserving the exact Inventory, layer and Production values.
- The FIFO projector reproduces the current verified issue splits and calculates replacement splits for receipt insertion or removal. It refuses a historical shortage, changed original split or an active intervening issue, and retains exact six-decimal layer values. In the public MR/GR tests the issue and reversal both change from 8 to 24 on insertion and return to 8 on removal. After a quantity and price edit they become 26. The receipt root atomically appends a complete linked split generation, paired zero-quantity Inventory value legs at the issue and reversal dates, and Production cost restatements. The original issue, reversal and FIFO consumption facts remain immutable.
- The fingerprinted plan checks the source receipt and approved cost, sealed issue/reversal facts and FIFO consumptions, single-pile stock, empty reversed Production pool, open periods and a bounded history. GR planning includes purchase-order quantities and rejects invoice settlement. It is rebuilt under the branch lock; the source batch is locked before the final recheck so a concurrent draft edit cannot be posted from a stale plan. The transaction-bound permit is activated only after the other posting, QA and PO checks. Existing correction chains and receipt cycles must reconcile before removal or repost.
- The cost-changing route requires the new FIFO reversed-issue generation and split tables and their SQL write guards. Fresh test databases create the tables from the development model and install `scripts/create-fifo-reversed-issue-guards.sql`; the script supplies guards only. The local ERPWeb database was checked read-only and did not contain the new tables. No migration or schema update was run there, so this case remains blocked in that database until its development schema and guards are updated. The route does not cover multi-line or multi-pile receipts, active downstream changes, output or finished-good descendants, counts, invoice settlement or wider dependency graphs.
